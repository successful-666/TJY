# 以太网 bring-up 说明

最后更新：2026-09-10

## 一、当前网络参数

| 项目 | 值 | 定义位置 |
|---|---|---|
| IP 地址 | 192.168.1.2 | `Core/Src` 外，见 `LWIP/App/lwip.c` |
| 子网掩码 | 255.255.255.0 | 同上 |
| 网关 | 192.168.1.1 | 同上（本轮修正） |
| MAC 地址 | 00:80:E1:xx:xx:xx，后三字节由芯片 UID 派生 | `LWIP/Target/ethernetif.c` |
| TCP 监听端口 | 5000 | `Core/Src/app_eth.c` 的 `APP_ETH_PORT` |
| DHCP | 关闭（纯静态） | `LWIP/Target/lwipopts.h` |
| PHY | LAN8720A，RMII，复位脚 PB14（低有效） | `LWIP/Target/ethernetif.c` |

## 二、本轮改动

1. **PHY 复位时序修正**：复位脉冲原本放在 `HAL_ETH_Start_IT()` 之后、链路已配置之后，
   现移到 `LAN8742_Init()` 之前（`PHY_PRE_CONFIG` 段）。原位置在网线未插时根本不会执行。
2. **MAC 地址唯一化**：改为 `00:80:E1` + 由 96 位 UID 折叠出的后三字节，避免多板冲突。
3. **网关修正**：`192.168.100.1` → `192.168.1.1`，与 IP 处于同一网段。
4. **TCPIP 线程栈**：1024 → 2048 字节（`lwipopts.h`）。
5. **新增 TCP 回显服务**：`Core/Src/app_eth.c` + `Core/Inc/app_eth.h`，
   由 `MX_LWIP_Init()` 末尾调用 `app_eth_init()` 启动。
6. **Keil 工程**：`Car_Robot.uvprojx` 中加入 `app_eth.c`。

## 三、验证步骤（使用另一台电脑测试）

### 步骤 1：编译并烧录

用 Keil 打开 `code/MDK-ARM/Car_Robot.uvprojx`，按 `F7` 编译、按下载按钮烧录到板子。
已经生成好的固件也可以直接烧：`code/MDK-ARM/Car_Robot/Car_Robot.hex`。

### 步骤 2：接线

测试电脑的**有线网口**用网线连到主控板网口。直连或经交换机都可以，
LAN8720A 支持自动翻转，不用管交叉线。

### 步骤 3：给测试电脑配一个同网段地址

主控板固定是 `192.168.1.2/24`，所以测试电脑必须有一个 `192.168.1.x` 的地址。

图形界面操作：设置 → 网络和 Internet → 高级网络设置 → 更多网络适配器选项 →
右键「以太网」→ 属性 → 双击「Internet 协议版本 4 (TCP/IPv4)」→
选择「使用下面的 IP 地址」，填：

| 字段 | 值 |
|---|---|
| IP 地址 | 192.168.1.100 |
| 子网掩码 | 255.255.255.0 |
| 默认网关 | 留空 |
| DNS | 留空 |

命令行操作（管理员身份运行 PowerShell）：
```
New-NetIPAddress -InterfaceAlias "以太网" -IPAddress 192.168.1.100 -PrefixLength 24
```
不用了要恢复回去：
```
Remove-NetIPAddress -InterfaceAlias "以太网" -IPAddress 192.168.1.100 -Confirm:$false
```

> 注意：如果测试电脑同时连着 WiFi，不用管它。有线网口这个静态地址会自动
> 为 `192.168.1.0/24` 建一条直连路由，不会影响上网。

### 步骤 4：第一关 —— ping 通

```
ping 192.168.1.2
```

能稳定回包说明 PHY、RMII、DMA、ARP、ICMP 整条链路都正常。

### 步骤 5：第二关 —— TCP 双向通信

方式 A：用网络调试助手（NetAssist 之类），TCP Client 模式连 `192.168.1.2:5000`，
随便发点内容，应该原样收到回显。

方式 B：在测试电脑的 PowerShell 里直接粘贴这一段：
```powershell
$c = New-Object Net.Sockets.TcpClient('192.168.1.2', 5000)
$s = $c.GetStream()
$b = [Text.Encoding]::ASCII.GetBytes("HELLO")
$s.Write($b, 0, $b.Length)
$r = New-Object byte[] 64
$n = $s.Read($r, 0, 64)
[Text.Encoding]::ASCII.GetString($r, 0, $n)
$c.Close()
```
最后一行应该打印出 `HELLO`。

这一步通了，就说明 netconn 收发、pbuf 池、回调链路都可用，
可以开始替换成真正的 CAN/485 控制协议。

### 附：一键自检脚本

`AI工作层/eth_test.ps1` 会把上面 1~5 步自动跑一遍并给出结论。
把这个文件拷到测试电脑上，然后在测试电脑上执行：
```
powershell -ExecutionPolicy Bypass -File "<脚本路径>\eth_test.ps1"
```

## 四、ping 不通时的排查顺序

1. 看 RJ45 上的链路灯是否亮；不亮先查网线、PHY 供电、25MHz 晶振、PB14 复位电平。
2. 若链路灯亮但 ping 不通，用 `arp -a` 看 PC 有没有学到 `00:80:e1:xx:xx:xx`，
   学不到说明收包路径有问题（DMA 描述符 / 中断）。
3. 确认 PC 防火墙没有拦 ICMP；确认 PC 网卡没被 VPN、虚拟网卡抢占路由。
4. 如果是从旧固件升级测试，注意 PHY 复位后需要等几秒自协商完成再 ping。

## 五、已知限制 / 待办

- TCP 服务当前为**单连接、回显模式**，协议未定义。下一步需要明确：
  帧格式（定长 / 长度域 / 分隔符）、连接数、心跳、异常处理。
- CAN1 已配置为 1 Mbps，但**未配置接收滤波器**，中断已开却收不到报文。
- 原理图上的 RS485 收发使能脚（`485_EN`）在 CubeMX 中没有对应 GPIO，
  需要先确认实际连接再分配。
- 应用层没有串口日志输出（MicroLib 未开启，也没有 printf 重定向），
  调试信息目前只能靠 PC 侧观察。若需要，可以单独加一路 UART 日志。
